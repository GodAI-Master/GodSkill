## Skills 一览

### `first-principles-decision`

用于购买、技术选型、产品设计、工作流、学习路线、商业策略、成本和风险比较等复杂决策。它会分离真实目标与用户已提方案，检查隐藏假设，搜索会影响结论的最新信息，比较替代路径，再给出明确可执行的建议。

### `no-repeat-skill`

用于将重复工作流、SOP、长提示词、团队经验、专家方法和现有 Agent Skill，转化为精简、可安装、可执行、可验证和可迭代的能力包。它不会一上来就创建大量文件，而是先用第一性原理重定义真实目标，检查“这件事必须做成 Skill”的假设，然后在一次性回答、文档、项目规则、记忆、模板、脚本、自动化和 Skill 之间选择成本最低且足以解决问题的载体。

只有当任务确实会复用、存在稳定的误判或重复解释成本、需要 Agent 根据语境做出判断，并且结果能够被检查时，它才会建议建立 Skill。进入构建后，它会定义应触发、不应触发和容易混淆的近邻场景；设计详细但有区分度的简介；把通用决策留在入口，把条件性知识、确定性脚本和产物模板按需分开；最后用结构、路由、端到端行为、安全和回归检查来验收。

该 Skill 还专门区分“文件格式没有错”和“Agent 真的会做对”这两种完全不同的证据，避免把 JSON 通过、关键词命中或自评报告误当成真实能力验证。对于公开发布或复刻第三方能力的场景，它会额外检查许可、归属、隐私、密钥、外部依赖和发布副作用，防止通过简单替换名称来规避原始许可条件。

适合的请求包括：

- “把我每周都要重复解释的流程做成 Skill。”
- “审查这个 Skill 为什么经常误触发，并直接修好。”
- “这套 SOP 到底应该做成 Skill、脚本还是项目规则？”
- “把这段长提示词重构为能在多个 Agent 环境中分发的能力包。”

## &#128161; 为什么需要这个 Skill？

当 AI 助手面对你的请求时，默认行为是「尽力执行你提出的方案」。这在简单任务中高效，但在复杂决策中可能是危险的——因为**你提出的方案只是你已知的路径，不代表最优解**。

**GodSkill 改变了这个范式。** 它会主动：

- 区分你的「真实目标」和你提出的「实现方法」
- 挖掘你没意识到但至关重要的信息
- 挑战你方案中未经验证的假设
- 寻找更简单、更稳定、更高上限、更适合 AI 时代的替代路径
- 在交付前进行对抗性复核

**它不是要证明你错了，而是要帮你看到你没看到的东西。**

## &#128260; 核心工作流

```
&#127919; 目标重定义  →  &#128270; 隐藏假设  →  &#128301; 信息差扫描  →  &#128256; 替代路径  →  &#9878; 反方审查  →  &#9989; 执行决策  →  &#128260; 对抗性复核
```

### 七步决策框架

| 步骤 | 名称 | 核心问题 |
|------|------|----------|
| **1** | 目标重定义 | 你真正想要的结果是什么？你提出的方法在多大程度上偏离了目标？ |
| **2** | 隐藏假设检查 | 你依赖了哪些未验证的前提？哪些是过时的行业惯例？ |
| **3** | 信息差扫描 | 有哪些你不知道但应该知道的工具、技术、规则、实践？ |
| **4** | 替代路径审查 | 有没有更简单/更稳/更高上限/更长期/AI 时代的替代方案？ |
| **5** | 反方与反常识 | 如果这方案失败，最可能死在哪里？有没有 20% 复杂度实现 80% 效果的捷径？ |
| **6** | 执行决策 | 明确的结论：原方案是否值得继续？最终建议走哪条路线？ |
| **7** | 对抗性复核 | 从反方视角再审视一遍，发现漏洞直接修正 |

**输出原则：结论先行。** 先告诉你答案和做法，再展示分析过程供你追溯。

## &#127919; 触发条件

### &#9989; 自动触发审查的任务

| 类别 | 示例 |
|------|------|
| **购买决策** | 买设备、软件、服务、订阅 |
| **技术选型** | 选择框架、语言、数据库、架构方案 |
| **产品设计** | 功能设计、交互设计、系统架构 |
| **工作流搭建** | 自动化流程、CI/CD、团队协作 |
| **学习路线** | 学什么、怎么学、资源选择 |
| **商业决策** | 定价策略、市场进入、竞品分析 |
| **旅行规划** | 目的地、路线、预算分配 |
| **长期工具** | 要用很久的软件/硬件/服务 |
| **成本比较** | 多方案成本效益分析 |
| **风险比较** | 多方案风险评估 |

### &#10060; 直接执行的任务

改写句子、润色文案、格式转换、翻译、简单代码修复、明确事实查询 —— 这类任务无需审查，直接完成。

> **判定优先级**：不确定时，默认启动审查。

## &#128736; 安装

### 方式一：手动安装

1. 下载本仓库。
2. 选择 `first-principles-decision/` 或 `no-repeat-skill/`。
3. 将整个 Skill 目录复制到目标 Agent 的 skills 目录；不要只复制 `SKILL.md`，否则关联资源会丢失。
4. 按目标 Agent 的要求刷新或重启。

### 方式二：克隆到 skills 目录

```bash
git clone https://github.com/GodAI-Master/GodSkill.git
```

然后将所需的 Skill 子目录复制到目标 Agent 的 skills 目录。

## &#128172; 使用示例

### 示例 1：购买决策

```
用户：我想买一台 Mac mini M4，用来远程使用 AI Agent，有什么建议？

GodSkill 响应：
&#128204; 执行决策：
  原方案需要调整。在用现有电脑零成本验证之前，不建议直接购买。
  推荐路线：现有电脑 + Tailscale 跑两周 → 确认需求 → 再决定买不买硬件。

&#128220; 分析过程：
  隐藏假设：必须买新硬件才能跑 Agent（不成立）、必须是 Mac（存疑）
  信息差：16GB 入门款已下架、Agent 瓶颈在内存不在 CPU
  替代路径：现有电脑免费方案、VPS 月租方案、x86 迷你主机方案
  ...
```

### 示例 2：技术选型

```
用户：我们项目要用微服务架构，选 Spring Cloud 还是 Kubernetes？

GodSkill 响应：
&#128204; 执行决策：
  先回答一个问题：你的团队多少人？QPS 多少？
  5 人以下、QPS < 1000 → 单体 + 模块化就够了，微服务是过度设计。
  ...
```

## &#128218; 设计哲学

GodSkill 强调六项核心原则：

| 原则 | 含义 |
|------|------|
| **不迎合** | 不是在帮你证明你的方案正确 |
| **不偷懒** | 每一步都必须有实质内容，不能跳过 |
| **不畏冲突** | 发现问题直接指出，不需要委婉 |
| **不罗列选项** | 最终必须给出明确建议，不让你自己从一堆选项中选 |
| **不依赖旧知识** | 涉及可能变化的信息，先搜索核实最新情况 |
| **结论先行** | 先说结论和做法，再展示分析过程 |
