# 安全与发布

## 使用时机

当 Skill 包含第三方内容、脚本、外部依赖、网络请求、密钥、用户数据、公开发布或可能造成损失的动作时读取。

## 来源与许可

复刻、翻译、重写或整合第三方 Skill 时：

1. 先读许可证、声明文件和仓库说明。
2. 区分不受表达限制的通用思路，与具体文字、代码、模板、图像和数据。
3. 如果会复制或改编受保护内容，就遵守保留通知、归属、同许可分发或商用限制。
4. 如果不想继承原作的身份标识或许可条件，采用洁净重建：只保留问题、可验证行为和通用方法，独立设计文字、结构、代码和测试。
5. 记录读取过的来源和采用的许可判断，即使这份记录不进入最终 Skill 包。

仅删除原作者姓名、品牌、特殊符号或文件头，不会让复制的内容变成新的独立作品。

## 权限和副作用

将动作按影响分类：

| 类型 | 例子 | 默认处理 |
| --- | --- | --- |
| 只读 | 查看文件、获取元数据 | 在用户已给范围内进行 |
| 本地可逆写入 | 新建文件、修改草稿 | 使用明确路径，保留用户无关改动 |
| 外部写入 | 发送消息、上传、提交、推送 | 确认在用户授权范围内，先解析精确目标 |
| 破坏性或高代价 | 删除、覆盖、付费、生产变更 | 明确授权、最小范围、回滚或恢复路径 |

不使用模糊通配符、未解析变量或大范围目录执行破坏性操作。

## 密钥、隐私和数据

发布前检查：

- API key、token、cookie、私钥、证书和真实凭证。
- 本机绝对路径、内网地址、私有仓库和内部账号。
- 用户姓名、联系方式、客户资料、未脱敏日志和业务数据。
- 图片、文档、测试样本的嵌入元数据。
- 失败输出中意外打印的环境信息。

敏感配置应由运行环境提供，Skill 仅说明变量或工具需求，不包含真实值。

## 依赖与供应链

- 每个外部包、二进制、远程脚本和服务都要有实际用途。
- 说明来源、版本范围、网络需求、账号需求和是否付费。
- 避免默认执行“下载并立即运行”的未审计命令。
- 依赖安装不是小事；当平台需要授权时，遵守该授权流程。
- 外部服务失效时要有清楚的失败信息和停止点，不反复产生付费或外部副作用。

## 发布前门槛

对公开分发的 Skill，确认：

- 名称、许可、仓库与产物的关系清楚。
- 没有未授权的第三方内容或必须保留却被移除的通知。
- 新环境中的安装和第一次调用已经测试，或清楚标注尚未测试。
- 所有链接、脚本和必需资源可用。
- 没有编辑器临时文件、缓存、本地构建物和与产品无关的证据文件。
- 说明已验证范围与未验证范围，没有用“可用”掩盖未运行过的测试。

使用 [review-report.md](../assets/templates/review-report.md) 作为审查交付格式，但只填写实际证据。
