# 平台适配

## 使用时机

当需要将同一能力分发到 Codex、Claude Code 或其他支持 Agent Skill 的平台时读取。

## 便携内核与平台外壳

将能力拆成两层：

### 便携内核

- 意图与排除项。
- 关键决策和操作顺序。
- 输入、产物和验收标准。
- 按需读取的参考、模板和脚本。
- 与平台无关的安全边界。

### 平台外壳

- 元数据字段和可视化展示信息。
- 自动触发或显式调用策略。
- 安装路径、包管理和发布方式。
- 工具、权限、沙箱和审批机制。
- 平台特有验证器和用户界面。

不为了表面一致而假设所有平台支持相同字段、目录和权限语义。

## Codex 适配

- 使用平台当前支持的 `SKILL.md` frontmatter 字段。
- 如果当前环境提供 Skill 创建器或校验器，创建或重构时先读取它的当前规则。
- UI 元数据与 Agent 指令分离，并保持名称和默认调用文本一致。
- 不在 Skill 中绕过文件、网络或外部动作的现有授权机制。

## Claude Code 适配

- 确认目标环境对 frontmatter、资源目录、工具授权和调用方式的当前要求。
- 用新会话测试路由，不用已经知道预期结果的同一会话充当独立评估。
- 把平台特有规则局部化，不覆盖便携内核。

## 其他 Agent 平台

在宣称兼容前确认：

1. 平台如何发现和选择 Skill。
2. 是否能读取链接的本地资源。
3. 是否能运行脚本，运行时使用什么工作目录。
4. 工具调用和外部写入需要什么授权。
5. 包内相对路径、文件名和字符编码是否保留。
6. 有没有平台自带的结构校验和路由测试。

没有实际安装和调用证据时，使用“结构可携带”或“待目标平台验证”，不要声称“已完全兼容”。

## 平台变化处理

平台规范、目录和元数据可能变化。当任务依赖当前规则时：

- 优先读本地安装的创建器、校验器和官方说明。
- 本地信息不足时，查询官方最新文档。
- 将平台特有变化限制在元数据或适配文件中，避免大面积改写通用方法。
