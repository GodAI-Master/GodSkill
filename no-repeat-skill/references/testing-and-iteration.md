# 测试与迭代

## 使用时机

当需要验证新 Skill、审计现有 Skill、修复失败或准备发布时读取。

## 证据层级

不同检查能证明的事情不同：

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 文件存在与格式检查 | 包的基本结构可读 | 会正确触发 |
| 链接、JSON、YAML 和脚本语法 | 机械结构没有明显错误 | 流程有用 |
| 关键词或语料检查 | 用例包含预期信号 | 真实模型会路由 |
| 新会话路由测试 | 当前模型与技能集中的选择表现 | 所有平台一致 |
| 真实任务执行 | 当前场景能交付结果 | 其他场景不会回归 |
| 多次回归与真实反馈 | 在已覆盖范围内具有持续证据 | 未测范围零风险 |

报告时只声称当前证据能支持的结论。

## 最小测试集

一个普通新 Skill 至少包含：

1. **结构检查**：名称、frontmatter、必需文件、链接和占位符。
2. **三类路由场景**：正例、反例、近邻例各至少一个。
3. **一个端到端行为场景**：用真实或高保真输入产生真实交付物。
4. **脚本测试**：每个新增脚本至少运行一个成功输入和一个失败输入。

影响多人、多项目、公开发布或高风险操作时，增加：

- 长输入、不完整输入、矛盾约束和工具失败的压力场景。
- 多 Skill 共存下的近邻路由。
- 权限被拒绝、用户中途改变要求和外部系统不可用的场景。
- 独立会话或独立评估者进行的前向测试。

## 路由用例设计

测试意图，不只测技能名称。

本 Skill 自带一组用于评估路由边界的 [route-cases.json](../evals/route-cases.json)。它是预期行为语料，必须在真实评估环境中执行后才能成为路由证据。

### 正例

- 明确点名 Skill 的请求。
- 不点名但语义完全符合的请求。
- 使用非标准说法、口语或领域词汇的请求。

### 反例

- 仅出现相同名词，但意图不同。
- 应直接执行的一次性简单任务。
- 用户只想了解概念，并未要求产出能力包。

### 近邻例

- 同样涉及流程，但真正需要的是自动化。
- 同样涉及提示词，但用户只要改写一次。
- 同样涉及评估，但用户要的是业务决策而不是 Skill 设计。

## 行为用例

使用 [behavior-case.md](../assets/templates/behavior-case.md) 记录：

- 初始状态与真实用户请求。
- 应触发的能力和不应触发的能力。
- 可观察的必须行为和禁止行为。
- 实际产物或对话记录。
- 结果、证据限制和失败原因。

不要只检查固定标题或一段特定文字。优先检查行为和产物是否满足必要条件。

## 失败到回归

每次修复按以下方式闭环：

1. 保存失败输入和可观察错误。
2. 判断根因在路由、指令、知识、工具、权限还是外部状态。
3. 做能够解决根因的最小修改。
4. 重跑失败场景。
5. 重跑受修改影响的正例、反例和近邻例。
6. 仅当结果可重现时，记录为通过。

## 深度适配

- **个人草案**：结构检查 + 三类路由 + 一个行为场景。
- **团队共用**：加入多用户样例、回归和维护责任。
- **公开发布**：加入许可、隐私、可携带性和安装验证。
- **高风险能力**：加入授权失败、回滚、人工复核和审计证据。

不因为类别名称而伪造成熟度。成熟度应由真实使用、失败修复和回归记录逐步提升。
