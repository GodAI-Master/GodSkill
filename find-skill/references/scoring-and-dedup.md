# 排序与去重规则

目标：同一份需求在不同时间、不同执行者手里，得到基本一致的排序结论。

## 一、三级去重

去重在排序之前完成。顺序不能颠倒，否则热门镜像会挤掉原始来源。

### 第一级：规范名归一

把名称统一为小写、去除空格与连字符、去除版本后缀与市场前缀，得到一个规范键。

- `Excel / XLSX` → `excelxlsx`
- `excel-xlsx` → `excelxlsx`
- `Xlsx Pro` → `xlsxpro`

规范键相同即视为同一候选簇。

### 第二级：来源标识归一

读取各市场携带的原始标识：

- SkillHub：`namespace.canonicalName`、`source`
- ClawHub：`install.reference`、`install.sourceUrl`
- 虾评：`id` 与 `owner_name`
- GitHub：`full_name`

来源标识相同即同一实体，即使名称已被二次改写。

### 第三级：描述指纹

前两级无法判定时，比较描述文本：取前 80 个字符归一化后计算相似度，同时取关键词集合做 Jaccard 系数。相似度大于等于 0.8 判为同簇。

这一步专门处理"同一技能被不同账号改名重复上架"的情况，仅靠名称无法识别。

### 簇内保留规则

按以下优先级保留一条作为代表，其余标记为镜像：

1. 官方内置（L1）
2. 本地已安装（L2）
3. 可追溯到原始仓库的发布者
4. 安全报告结论明确的条目
5. 采用度更高者

镜像不得单独进入候选表，可在代表条目下注明"另有 N 处镜像"。

## 二、四维评分

总分 = 能力匹配 × 0.40 + 可信证据 × 0.25 + 采用度 × 0.20 + 维护活跃 × 0.15

每个维度先归一到 0 至 100，再加权。禁止用单一热度指标代替。

### 能力匹配（0-100）

| 判断 | 分档 |
| --- | --- |
| 描述直接命中交付物，且覆盖关键约束 | 85-100 |
| 描述命中交付物，关键约束未提 | 65-84 |
| 描述命中领域但交付物不明确 | 40-64 |
| 仅在标签或副产物中提及 | 10-39 |

关键约束指用户明确要求的边界，例如"必须能出图"、"必须本地处理"、"必须保留宏"。

### 可信证据（0-100）

满足项累加，上限 100：

- 发布者通过平台认证：+30
- 平台安全报告结论为无风险：+30（多份报告一致再 +10）
- 可追溯到原始开源仓库：+20
- 官方上架标记：+10
- 无任何安全证据：直接判为 0 至 30 区间，并标注未验证

### 采用度（0-100）

对下载或安装量取对数后归一：`min(100, 20 × log10(量 + 1))`。

对数压缩的目的是避免头部技能垄断排序。量级参考：100 次约 60 分，1000 次约 80 分，10000 次约 100 分。

零安装不等于零价值，仅在"上架时间极短且无任何反馈"时才降档。

### 维护活跃（0-100）

- 近 3 个月有版本更新：80-100
- 近 6 个月有更新：60-79
- 近 12 个月有更新：40-59
- 超过 12 个月无更新或无版本信息：0-39

## 三、强制降级条件

命中任意一条，最终推荐顺位下调，并写明原因：

1. 描述宣称的能力在正文中找不到依据
2. 安全报告缺失且无法追溯到原仓库
3. 仅有聚合市场镜像，找不到上游
4. 安装量为零且上架不足 30 天
5. 同一描述在多个市场由不同账号重复上架，疑似刷榜
6. 需要外部账号授权才能使用，但用户场景无法提供

## 四、示例：同一个需求下的去重与排序

需求：处理 Excel 并输出图表。观测到的原始候选包括内置技能、两个聚合市场里的多条同描述条目、官方开源技能、若干新上架中文技能。

处理过程：

1. 规范名归一后，`Excel / XLSX` 与 `excel-xlsx` 合并为一簇。
2. 该簇内发现两个市场计数差异极大，标注为口径不同，不合并计数、不跨市场排名。
3. 描述指纹比对发现两条几乎一致的英文条目，判为重复上架，保留原始仓库可追溯的一条。
4. 官方开源技能因"可追溯到原仓库 + 描述明确含图表"获得高可信证据分，即使其下载量口径与聚合市场不可比，仍排在首位。
5. 新上架中文技能功能描述最全，但零安装且上架时间短，按强制降级条件第 4 条下调，标注为"待实测"。
6. 内置技能在采用度维度取中性分，最终因零安装成本与原生图表对象能力进入首推。

输出结论按"零成本首选、通用主力、场景专用、待实测"四档呈现，而不是一条从高到低的单一榜单。分档比排名更能表达选型意图。

## 五、常见错误

- 先排序再去重，导致镜像挤占真实来源。
- 把不同市场的下载量放同一列排名。
- 用星数代替可信度，星数只反映关注度。
- 把聚合市场的条目当成一手来源，不回溯上游。
- 用单一总分掩盖维度差异，例如高热度低能力匹配的条目被排到前面。
- 对零安装的新技能直接判死，忽略其可能填补能力空白。
