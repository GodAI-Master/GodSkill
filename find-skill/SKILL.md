# Find Skill

把一个模糊需求，变成一份**可追溯、可复核、可复现**的技能选型结论。

核心不是"搜到很多"，而是"每一层都跑过、每一条来源都可点开、每一句能力判断都有原文依据"。

## 核心约定

这些是硬规则，任何一条被跳过都必须在输出中标注，不得静默省略。

1. **六层是执行清单，不是修辞。** 未执行的层写"未执行+原因"，零命中的层写"零命中"，接口失败的层写"failed+状态码"。禁止在只跑了三层的情况下输出"已六层联合检索"。
2. **先本地后远程。** 本地已命中的能力优先推荐；远程更热门不构成替换理由。
3. **默认只推荐，不安装。** 安装必须由用户显式确认，且展示来源、安全证据与落盘路径。
4. **同源去重优先于覆盖数量。** SkillHub 与 ClawHub 存在联邦关系，同一技能不得在两个市场被重复计数。
5. **数字必须带口径。** 同一技能在不同市场计数不同，引用下载量时标注来源与观测时间。
6. **推断与事实分离。** "描述里提到 chart"是事实；"能画图"是推断。推断必须标注依据强度。
7. **零命中是有效结果。** 承认没有合适的技能，比凑满候选表更有价值。

## 六层执行顺序

层间串行、层内并发。详细端点、响应字段与失败模式见 [六层端点与字段](references/layer-endpoints.md)。

| 层 | 位置 | 产出 | 典型失败 |
| --- | --- | --- | --- |
| L1 官方内置 | 客户端插件缓存中的 builtin 目录，逐个读 SKILL.md frontmatter | 无需安装的兜底能力 | 多版本共存导致重复计数 |
| L2 本地已安装 | 用户级 skills、工作区级 skills、市场缓存目录 | 已装能力，零成本复用 | 只列目录名、未做语义匹配 |
| L3 SkillHub | lightmake 检索接口，关键词需 URL 编码 | 中文与英文商业技能 | 低分噪声、同描述镜像重复上架 |
| L4 虾评 | xiaping 检索接口，注意域名是 coze.com | 中文场景技能，官方标状态 | 需要先加载其指南技能才能取下载链接 |
| L5 ClawHub | clawhub 检索接口，搜索路由是 api/v1/search | 生态最大、采用度最高的一批 | 详情路由与搜索路由不同，误用会返回 404 |
| L6 GitHub | repositories 搜索；代码级搜索需令牌 | 开源技能与可审计源码 | 无令牌时代码级搜索不可用，覆盖面下降 |

L1 与 L2 的扫描用 [本地层扫描脚本](scripts/scan_local_layers.py)，不靠人工肉眼比对目录名。

## 执行流程

### 1. 拆解场景

不要用用户原话直接搜。拆成四类词，每类至少一组：

- **任务动词**：处理、分析、生成、转换、审计
- **交付物名词**：表格、报告、图表、仪表盘、海报、PPT
- **领域限定**：财务、招聘、电商、教育
- **中英同义词**：图表与 chart、可视化与 visualization、表格与 spreadsheet 与 xlsx

只用中文词搜英文市场、或只用英文词搜中文市场，都会系统性漏召回。

### 2. 扫本地两层

运行扫描脚本，得到 L1 与 L2 的去重清单与本地匹配分。本地零命中也要记录，不能跳过。

### 3. 并发检索远程四层

每一层记录三件事：执行状态、命中数、原始响应是否可解析。不要只保留最终候选，失败状态本身就是结论的一部分。

### 4. 归一化去重

按 [排序与去重规则](references/scoring-and-dedup.md) 做三级去重，合并同源镜像，保留证据最强的一条。

### 5. 四维排序

能力匹配、可信证据、采用度、维护活跃，各自独立给分，禁止用单一"热门度"排序。评分细节与降级条件见同一份参考文件。

### 6. 输出覆盖矩阵

按 [输出契约](references/output-contract.md) 生成。覆盖矩阵是必选段落，不是可选附录。

### 7. 安装门禁

仅在用户明确要求安装后执行，且逐条确认：来源、安全报告状态、目标目录、是否覆盖同名技能。

## 排序摘要

| 维度 | 权重 | 判据 |
| --- | --- | --- |
| 能力匹配 | 40 | 描述与交付物是否直接对应，是否覆盖用户的关键约束 |
| 可信证据 | 25 | 发布者认证、安全报告结论、是否官方仓库可追溯 |
| 采用度 | 20 | 下载或安装量取对数后归一，警惕短期刷量 |
| 维护活跃 | 15 | 版本迭代时间与版本数量 |

出现以下情况必须降级并说明：描述与能力不符、安全报告缺失、下载量为零且上架时间极短、仅有镜像无原始仓库。

## 输出契约

一份合格输出必须同时包含：覆盖矩阵、关键词组、候选表、零命中与失败说明、未执行项。模板与合格示例见 [输出契约](references/output-contract.md)。

候选表每行至少包含：名称、所属层、来源标识、热度与口径、能力证据（原文片段或字段名）、主要风险。

## 失败与降级

| 情况 | 处理 |
| --- | --- |
| 无 GitHub 令牌 | 只做仓库级搜索，标注代码级搜索未执行，说明可能漏掉散落技能 |
| 市场接口超时或非 200 | 标记失败并记录状态码，最多重试两次，不静默跳过 |
| 安全报告字段缺失 | 标为未验证，不写成安全 |
| 候选仅存在于聚合市场 | 标注上游来源，提示去原始仓库复核 |
| 安装量为零 | 标注上架时间，提示缺少真实使用验证 |

## 与其他能力的边界

- 需要**新建、重构、审查** Skill：交给 `no-repeat-skill`，本技能只负责发现与选型。
- 用户只问一个事实、只做一次查询：不触发。
- 用户已明确说出要用哪个技能：直接加载即可，不触发检索。
- 用户要求把候选**做成对比报告或评测**：本技能只提供选型依据，评测设计属于另一条链路。

## 验证边界

`scripts/scan_local_layers.py` 只能证明本地两层的目录结构与 frontmatter 可解析，不能证明远程四层的实时可达性，也不能证明候选技能在真实任务中的表现。远程层的结论始终带有观测时间，市场数据会变。
