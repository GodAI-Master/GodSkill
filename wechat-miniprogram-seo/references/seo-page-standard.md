# 微信小程序通用 SEO 页面设计与实现规范

## 目标与边界

把 SEO 当作小程序的内容能力来规划，而不是上线后的关键词补丁。建立一套从搜索需求、公开页面、页面发现到用户下一步行动的内容体系。

核心目标是让页面**可发现、可直接访问、可理解、可匹配并对用户有用**。开发者能控制的是页面质量和抓取条件；微信是否抓取、收录、展示或排序由平台决定，因此本规范不承诺收录或排名。

基本单位是具有明确搜索意图的独立页面，而不是小程序本身或关键词数量：

> 有独立搜索价值的公开内容，应有稳定、可直接打开的页面地址。

## 一、页面体系

业务页面负责完成登录、操作、支付、个人记录等流程；SEO 公开内容页面负责回答用户在微信里搜索的问题。两套页面可以共享数据和组件，但公开内容不应被业务状态挡住。

常见的公开页面结构：

```text
SEO 入口页
  └── 分类或聚合页
        └── 搜索意图详情页
              ├── 相关详情页
              └── 后续业务入口
```

项目可以采用不同页面路径。重要的是建立稳定、可遍历的页面关系，而不是照抄某个目录名。至少应有一个 SEO Hub（公开内容入口），并让符合条件的详情页从 Hub 或其他公开页面可达。

## 二、页面准入条件

将同时满足以下条件的页面视为“可索引候选页”：

1. 有独立且稳定的页面地址，可以从地址直接打开。
2. 页面初始化只依赖 URL 和公开数据，不依赖上一页传入的临时对象、`eventChannel`、`globalData` 预加载或访问顺序。
3. 未登录时能先看到完整的核心公开信息。
4. 页面有明确主题、独立标题和真实可见正文，能回答一个实际问题。
5. 有其他公开页面链接到它，也能从它继续访问相关公开页面。
6. 页面数据处于已发布状态；内容完整、不过度重复，并且具有持续的用户价值。
7. sitemap 允许该页面路径被索引，小程序后台也已开启相应页面收录能力。

只有标题和按钮、只有关键词但没有答案、内容相互复制、核心信息为空或被登录墙遮住的页面，不应加入可索引页面集合。

## 三、搜索词与页面主题

不要采用“一个关键词建一个页面”。先识别用户要完成的任务，把意思相同的表达聚为一个搜索意图，再为该意图建立一个页面。

例如，“几点开门”“几点关门”“营业到几点”通常属于同一个营业时间意图。相反，“营业时间”和“地铁怎么去”解决不同问题，应分别组织页面。

建立新页面前先问：

- 这是不是一个真实且独立的用户问题？
- 已有页面能否在补充内容后回答它？
- 新页面能提供哪些独有、可核验的信息？
- 内容变化后谁来更新，失效时如何下线或合并？

目标是覆盖有效搜索意图，而不是堆大页面数。热词应来自实际搜索数据或清楚标注为编辑整理的常见需求；没有数据时，不要把人工挑选的词说成实时热度排名。

## 四、稳定 URL 与冷启动

使用简单、可长期复用的参数，例如 `slug` 或内容 ID；不要把复杂 JSON、临时来源、随机值、时间戳或会话信息塞进 URL。一个内容长期对应同一个地址，入口和排序变化不应改变它。

直接访问应完成：

```text
解析 URL → 读取已发布公开数据 → 设置页面标题 → 展示正文 → 提供下一步
```

验收时彻底关闭小程序，从目标 URL 直接打开，不先访问首页，不登录，也不预热前置页面。缺少或无效参数时给出清晰的不可用提示和有效入口，不得渲染另一条内容来冒充目标页。

## 五、标题与真实正文

标题要准确说明页面的主题和必要限定信息。用户只看标题就应大致知道页面解决什么问题。详情、内容、更多、结果等泛化标题不够清晰；所有页面套同一个标题也会削弱页面区分度。

小程序可在内容加载后用 `wx.setNavigationBarTitle` 设置页面标题。标题必须与用户看见的正文一致。

正文至少要包含主题解释、能回答问题的具体内容、必要的时效或核验说明、核心操作入口和真正相关的后续链接。关键词只在自然表达中出现；禁止隐藏文本、关键词堆积和爬虫专用内容。爬虫看到的内容应与普通用户看到的内容一致。

动态或本地生活信息要显示来源、最近核验时间、有效期或待确认状态。过期、冲突或未经核实的事实不能写成确定结论；页面可以明确说信息待核验，并引导用户查看可靠的下一步。

## 六、公开内容与身份验证

采用“公开内容优先”：先让用户看懂公开信息，再在收藏、同步、购买、提交或访问个人数据等确有需要的操作上验证身份。

不要在展示搜索落地页核心内容之前强制登录、授权或绑定手机号。公共正文由公开接口或不需要身份的数据源提供；私人信息与公开页面数据分开。

## 七、内链与孤岛页

SEO 页面发现关系优先使用小程序 `<navigator>` 组件，例如：

```xml
<navigator url="/pages/seo/detail?slug=sample-topic">
  查看这个问题的完整答案
</navigator>
```

将 `navigator` 用于 SEO Hub 到分类页、分类页到详情页、详情页到相关详情页等公开内容发现路径。业务交互仍可按项目工程习惯使用 `wx.navigateTo` 等 API。

每个可索引详情页至少有一个公开上级入口和合理的相关链接。没有任何公开页面指向的详情页是孤岛页。相关链接必须解决相邻问题，不要为了数量而互相循环或链接到下架内容。

## 八、sitemap 与页面收录范围

小程序根配置中的 `sitemap.json` 是页面准入控制，不是“越开放越好”的设置。优先明确允许 SEO Hub、完整公开的分类页和详情页，再按微信当前规则排除其他页面；不要无差别允许整个应用。

通常不应放开的内容包括登录和授权页、个人资料、收藏或历史记录、编辑和发布流程、支付流程、临时结果、中间步骤、无内容页以及依赖私人数据的页面。

示意配置如下，具体规则匹配方式与字段以微信开发者文档当前版本为准：

```json
{
  "desc": "仅开放公开搜索内容页",
  "rules": [
    { "action": "allow", "page": "pages/seo/index" },
    { "action": "allow", "page": "pages/seo/detail" },
    { "action": "disallow", "page": "*" }
  ]
}
```

同时检查 `app.json` 指向的 sitemap 文件路径，以及微信公众平台中的页面收录开关。配置完成只表示技术上允许，不代表平台已经抓取或收录。上线前按官方最新配置说明核对规则优先级、参数匹配和管理后台设置。

## 九、原生页面与动态内容模板

需要进入小程序搜索的核心内容应由小程序原生页面呈现。不要把主体内容全放在 `web-view` 中，也不要只为爬虫生成另一份内容。

使用“一个原生页面模板 + 多个已发布内容实例”承载不同主题。示例数据模型：

```text
SEO_PAGE
  id, slug, title, summary, content, category
  relatedPages, status, indexable
  searchIntent, publishTime, updateTime, expireTime
```

页面启动时从 URL 解析稳定标识，读取公开且已发布的内容，设置对应标题，展示正文并加载真实相关链接。若内容未发布、已下线、超过有效期或不满足质量要求，不要把它作为有效入口展示或继续推荐。

## 十、发布、维护与合并

```text
发现搜索需求 → 判断现有页面能否回答 → 聚类搜索意图
→ 创建或更新内容实例 → 设置稳定 URL 和标题
→ 补充真实正文 → 建立 navigator 内链 → 检查 sitemap
→ 冷启动验收 → 发布 → 观察页面与用户反馈
```

为内容维护草稿、已发布、已更新、已合并和已下线等状态。两个页面后来确认服务同一意图时，合并内容并保留一个主要页面，及时清理旧链接。运营者需定期核查动态数据、失效页面和过时链接。

## 十一、持续观察

围绕页面是否真的可用来复盘，而不是只看创建了多少关键词页：

- 有多少真实搜索意图已经有完整、有效的公开页面回答。
- 直接打开成功率、无效链接和已下架内容的数量。
- 内容核验是否过期，相关页面链接是否仍然有效。
- 微信后台能够提供的收录与搜索进入数据，以及落地后的下一步操作情况。

只有在平台实际提供对应数据时才报告收录量、搜索来源或转化指标；本地代码检查不能代替这些数据。

## 十二、上线前检查清单

### URL 和访问

- [ ] 每页有稳定、简洁且主题明确的地址。
- [ ] 直接冷启动可访问，不依赖前置页面或登录。
- [ ] 无效、下架或未发布内容有明确处理。

### 内容和用户体验

- [ ] 页面解决一个清楚的搜索意图。
- [ ] 标题与可见正文一致，信息真实且足够完整。
- [ ] 时效信息标明核验时间、来源或待确认状态。
- [ ] 核心公开信息先展示，再请求身份权限。
- [ ] 页面有实际可用的下一步和相关公开链接。

### 发现和索引准入

- [ ] Hub、分类和详情页之间存在可遍历的 `navigator` 链接。
- [ ] 没有孤岛页、重复页或指向下架内容的链接。
- [ ] sitemap 只开放符合条件的公开页面。
- [ ] 微信后台页面收录设置与当前发布版本相符。
- [ ] 不将 sitemap 配置误报为已被收录。

### 工程验证

- [ ] 路由、标题设置、公开数据读取和异常兜底通过项目检查。
- [ ] sitemap JSON 有效，路径能对应 `app.json` 页面。
- [ ] 在微信开发者工具中验证直接访问和内容展示。
- [ ] 真实微信搜索结果的收录状态另行观察，不以本地测试替代。
